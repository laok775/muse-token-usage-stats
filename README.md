# Muse Token 用量统计

一个给 Muse 做的 Token 用量统计插件：放在侧边栏，每小时自动刷新，展示本周额度用量、累计输入/输出、近 14 天用量趋势、各来源占比、时间段分布、最近 7 天最烧 Token 的任务、压缩事件和内容分析（消息来源、关键词云、话题分布）。

> 这个仓库不是插件本身的源代码，而是一份搭建说明。Muse 的插件（Space）是每个用户自己环境里的全栈应用，不能直接跨账号安装；但数据表和命令在每个 Muse 上都是一样的，照着 `BUILD.md` 做，任何一个 Muse 都能在自己的环境里搭出同样的插件。

## 功能

- 总览：本周免费额度用量（进度条 + 重置倒计时）、额外 Token 余量、累计输入/输出 token、消息数、当前上下文占用
- 近 14 天每日用量柱状图 + 明细表
- 来源占比：主对话 vs 后台任务/子代理
- 时间段统计：按小时（+星期）分布
- 花钱大户：最近 7 天烧 Token 最多的 Top 10 任务，同名任务合并，可展开看每次运行明细；后台任务显示真实任务名而非 ID
- 压缩事件：每次上下文压缩前后的 token 数
- 内容分析：消息来源（回复 / 主动 / 定时任务，启发式标注）、关键词云（用户和 Muse 各一朵，点词看原文摘录）、话题分布（规则分类）
- 每小时自动刷新 + 手动刷新按钮

## 怎么用

1. 把 `BUILD.md` 全文发给你的 Muse，或者直接说：“按这个仓库的 BUILD.md 给我做一个 Token 用量统计插件”。
2. Muse 会在你的侧边栏建好插件并装好每小时刷新。
3. 首次数据需要等一次刷新完成（约一两分钟）。

## 数据来源与口径

- 用量明细来自 Muse 内置数据库 `agent.agent_message_token_usage`（每条消息的 input/output token；`created_at` 是 epoch 秒）。查询见 `queries.sql`。
- 每周额度与重置时间来自 `subscription-status status` 命令。
- 当前上下文占用来自 `muse.session_status`。
- 口径说明（插件内也有）：
  - input 包含每次调用重发的整个上下文窗口，所以数字看起来很大；这是计费方式，不是 bug。
  - 数据库里的数字和账单的每周百分比是两套不同的表，不会完全对得上。
  - 缓存 token 和推理 token 没有数据源（`agent.token_usage` 明细表是空的），所以不展示。
  - 消息来源、关键词、话题分布是启发式/规则分类，标注为近似值。

## 不包含什么

- 不含任何个人用量数据、账号 ID 和截图；仓库里只有做法。
- 不做烧钱预测（可以自行加上）。
